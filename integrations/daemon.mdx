[**DAEMON**](https://www.daemonide.tech) is an Electron-based agent IDE for Solana that lets developers build, run, and approve autonomous agents from a desktop terminal. Every DAEMON workspace ships with Voight as its observability layer — out of the box, no separate setup beyond pasting an API key.

DAEMON's own integration guide lives at [daemonide.tech/docs/voight-observability](https://www.daemonide.tech/docs/voight-observability).

## How DAEMON uses Voight

DAEMON emits **reasoning, action, tool, decision, transaction, and error** events to Voight so a run can be reviewed both during and after execution. Inside Voight's dashboard, DAEMON activity surfaces alongside any other agent source you've connected — same timeline, same filters, same cost math.

| What DAEMON streams | Where it lands |
|---|---|
| Agent runs, tool calls, approval decisions | Live timeline, grouped by session / agent / model / outcome |
| Solana transactions | Trace detail with on-chain context |
| Errors + denials | `/dashboard/errors` clusters with resolution |
| Cost per model / per session | `/dashboard/ai-apps` Cost over time + Models tab |

## Architecture

DAEMON uses Voight's [raw HTTP path](/sdk/http-api) — `POST https://api.voight.xyz/v1/events` — directly from the **Electron main process**. This keeps the Voight API key inside DAEMON's secure key store and prevents any exposure to renderer code or the agent runtime itself.

The full event schema (`agentId`, `timestamp`, `type`, `toolExecuted`, `outcome`, `durationMs`, plus DAEMON-specific detail nested under `metadata.sessionId` etc.) is documented in the [Events reference](/api-reference/events).

## Privacy — three levels, scrubbed locally

DAEMON respects Voight's [three-level privacy model](/privacy/overview): events are scrubbed locally in the main process **before transmission**, so sensitive content never leaves the machine in the clear.

| Level | Behaviour | When to use |
|---|---|---|
| **Minimal** | Metadata only — tool names, timing, outcomes, tokens, USD. No prompts or responses. | High-sensitivity workspaces, shared screens |
| **Standard** (default) | Full content with PII / API key / wallet patterns scrubbed via [12 named patterns + Luhn-validated cards](/privacy/pii-patterns) | Most production agents |
| **Full** | Everything as-is | Internal debugging only |

PII patterns covered include API keys (`sk-*`, `vk_*`, AWS, GitHub, Slack), JWTs, PEM blocks, emails, phones, credit cards. Full list in the [PII patterns reference](/privacy/pii-patterns).

## Setup inside DAEMON

DAEMON users follow these steps inside the IDE — no code changes required:

1. **Generate a Voight key** in `voight.xyz/dashboard/settings` (one-click). The key is shown once and prefixed `vk_`.
2. **Open DAEMON Settings → Integrations → Voight Observability** and paste the key.
3. **Pick a privacy level** (Standard recommended for most workspaces).
4. **Test connection** — DAEMON sends a synthetic event and confirms it lands in your Voight dashboard.
5. **Run an agent.** Every event now streams to Voight in real time.

The full step-by-step lives in DAEMON's own docs: [Voight Observability — daemonide.tech](https://www.daemonide.tech/docs/voight-observability).

## Safety guarantees

- **API key encrypted** through DAEMON's secure key system — never exposed to the renderer process or to running agents.
- **Events scrubbed before queueing** — privacy filtering happens before the HTTP request is built.
- **Retry-aware** — DAEMON honours Voight's HTTP status codes (5xx + 429 retry with backoff; 4xx skip).
- **Fire-and-forget** — Voight ingestion never blocks the agent. If `api.voight.xyz` is unreachable, the event is swallowed locally and the agent continues.
